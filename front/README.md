## Что реализовано

Этот сценарий помогает пользователю построить путь обмена в три понятных шага:

```text
Мой активный товар → Желаемый товар или категория → Следующий возможный обмен
```

Пользователь выбирает своё активное объявление и товар, который хочет получить. Затем frontend передаёт выбранные идентификаторы в API поиска маршрута `GET /search/chain` и показывает найденный путь и подходящие варианты следующего обмена.

## Пользовательский сценарий

1. Пользователь выбирает товар, с которого начинает обмен.
2. Выбирает конкретный желаемый товар либо категорию.
3. Нажимает «Построить цепочку».
4. Получает маршрут, видит текущий товар, цель, число оставшихся обменов и варианты следующего шага.
5. Может отправить одно или несколько независимых предложений обмена.

## Интересные детали реализации

- **Адаптивный сценарий.** На компьютере оба шага формы отображаются одновременно. На мобильном устройстве форма работает как последовательный сценарий: «Продолжить» и «Назад» переключают шаги, не перегружая экран.
- **Валидация.** Построение маршрута доступно только после выбора стартового товара и цели. Для старта доступны только активные объявления текущего пользователя.
- **Состояния интерфейса.** Обработаны загрузка данных, отсутствие активных товаров, отсутствие найденного маршрута, ошибка API и успешная отправка предложений.
- **Прозрачность маршрута.** На странице результата пользователь видит, что у него сейчас, к чему он движется и какой обмен нужно совершить следующим.
- **Feature-Sliced Design.** Логика формы расположена в `src/features/routeBuilder`, рекомендации — в `src/features/routeRecommendations`, API и типы — в `src/entities`, а экран результата — в `src/pages/route`.

## Запуск frontend

```bash
cd front
npm install
npm run dev
```

Для запуска всего проекта вместе с API и базой данных используйте команду из корневого README:

```bash
docker compose up --build
```

## Использование инструментов на основе ИИ

При работе над frontend применялись инструменты на основе ИИ. Они помогали
рефакторить код, находить логические ошибки, быстрее готовить локальные правки
и создавать демонстрационный образец продукта на основании результатов
глубинного интервью. Все предложенные изменения проверялись командой, а
ответственность за продуктовые решения и итоговую реализацию оставалась за
разработчиками.
